## 2. Objective

Investigate failed and successful authentication events associated with a lab account and source IP address. Review authentication result codes, establish the observed event sequence, inspect the associated Defender case, and verify the case-management automation.

The objective is to demonstrate an evidence-based SOC investigation workflow without assuming that authentication failures establish malicious activity.

## 3. Investigation Scope

The investigation used Microsoft Entra ID `SigninLogs` records from the preceding 24 hours, filtered by the lab account and source IP.

**Account:** `ananthan@personalcybersecuritylab.onmicrosoft.com`

**Source IP:** `157.51.230.238`

**Location shown in logs:** India (`IN`)

**Application context:** Azure Portal and Office365 Shell WCSS-Client were visible in the reviewed timeline.

These findings apply to the selected account, IP address, and time range. They should not be generalized to other accounts or activity outside that scope.

## 4. KQL Investigation

The investigation queries are maintained in:

`kql/authentication/day15-end-to-end-investigation.kql`

The queries support three investigation activities:

1. Reviewing authentication events chronologically.
2. Summarizing successful, invalid-credential, and other events.
3. Examining authentication result codes and their descriptions.

The available result-code summary showed the categories but did not display the event count for each individual code. The distribution of the three other events should therefore not be inferred from that screenshot alone.

## 6. Authentication Timeline Findings

The chronological query showed the following sequence among the visible records:

1. A successful Azure Portal sign-in.
2. Two failed Azure Portal sign-ins with result code `50126`.
3. Subsequent successful Azure Portal sign-ins.
4. Successful sign-ins associated with Office365 Shell WCSS-Client.

The two visible invalid-credential failures occurred approximately 78 seconds apart.

Both successful and failed authentication events were associated with the same account and source IP in the query results.

### Analyst Interpretation

The observed pattern warrants investigation because invalid-credential failures occurred alongside successful sign-ins.

However, the available evidence does not establish that the failures were generated by an attacker, that a brute-force attack occurred, or that the account was compromised.

The observed failures also do not, by themselves, prove that the successful sign-ins were caused by the same authentication attempt sequence.

The investigation should not be presented as proof that this specific detection matched unless matching query results or alert evidence establish that relationship.

The lab includes automation for tagging relevant cases and creating an investigation task.

* The task `Review Repeated Invalid Credential Attempts` was present.

### Task status

The investigation task was displayed with its status set to `Not set`. The case remained Active and Unclassified.

Therefore, the evidence demonstrates successful task creation and case tagging, but not completion of the investigation task or resolution of the case.

## 10. Investigation Assessment

**Assessment:** Authentication activity investigated; malicious activity not confirmed.

The observed telemetry contained invalid-credential failures and successful sign-ins for the same account and IP. The case and its associated alert were reviewed, and the lab's case-tagging and task-creation automation was verified using captured execution evidence.

The available evidence is insufficient to conclude that a brute-force attack or account compromise occurred.

The case remains Active pending further validation. This is a deliberate evidence-based disposition, not a claim that the case has been resolved.
